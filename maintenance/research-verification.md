# Research verification and comparative dogfood

Maintainer-only evaluation guidance; this file and `tests/` are not installed runtime resources. Installation, receipt binding and operating permissions remain authoritative in [installation](../references/installation.md). This is a small question-to-proof map, not a research allowlist, mandatory user questionnaire or model-grading dependency. Keep financial observations, host traces and comparative answer packets outside the distributable package. Do not copy another skill's content into the candidate.

## Skeptical feedback triage

For each finding, retain the exact question, first answer, relevant attempted tool calls, tested package identity, claimed defect and smallest evidence needed to decide it. Separate observation from reviewer inference; a convincing critique is not financial proof. Check the current candidate and applicable scope, not merely a version label or an older review.

| Classification | Evidence that distinguishes it | Appropriate response |
|---|---|---|
| Missing guidance | Applicable rule or route genuinely absent after checking the entry path and linked evidence | Add the smallest rule at its existing owner; add a behavioral case where useful. |
| Buried guidance | Rule exists, but the natural entry route does not expose it before the relevant decision | Fix navigation or a short local pointer, not a second long rulebook. Test natural discovery without telling the agent which reference to read. |
| Ignored guidance | Trace shows the relevant instruction was available/read but the answer or action contradicts it | Preserve the failing answer and replay; investigate conflicting instructions, task interpretation and host/model behavior. Repetition alone is not a fix. |
| Mechanically preventable defect | A reproducible consumer invariant fails: ABI ambiguity, wrong units, stale confirmation, false zero, dropped checkpoint or retrieval after terminal denial | Fix the authoritative implementation and add an adversarial synthetic regression through the real consumer path. Do not replace accounting proof with file-wiring assertions. |
| Incorrect reviewer premise | Critique assumes an absent capability, wrong product, incompatible unit/beneficiary, outdated revision or unsupported economic equivalence | Correct the premise with scoped evidence; do not change sound accounting to satisfy it. Existing Book CLI support, for example, does not permit resetting a replay's exhausted budget. |
| Unresolved evidence or host limit | Trace lacks observations, access was denied, tool/discovery failed or the claimed behavior cannot be inferred from the supplied evidence | Record the gap and any useful partial answer; do not manufacture a bug, zero, live success or sandbox claim. |

A finding can have multiple causes. Record disposition as accepted, rejected with evidence, or unresolved; state the causal fix and remaining proof limit. Distinguish elapsed collection from approval waits and response delivery. Inspect any proposed repair against the original first answer; repaired follow-ups do not erase first-answer failures. Do not broaden retries, weaken denial handling or invent a financial reconciliation merely to make a review pass.

## Exported-runtime machine acceptance

The existing [CI workflow](../.github/workflows/validate.yml) verifies a committed export and reproducible archives, then runs `AnalyticsCLI.test_runtime_success_and_terminal_denial_consumer_contract` from [tests/test_cli.py](../tests/test_cli.py) with `--runtime-root` selecting that export. [tests/test_package.py](../tests/test_package.py) exercises the same consumer case on a reviewed test export. The [external fixture harness](../tests/cli_fixture.py) stays outside the strict runtime tree; only the exported scripts/assets implement collection and output.

The fixture provides raw synthetic transport, not cached chain data or preconstructed consumer answers. Isolated Python and an audit hook installed before runtime imports forbid socket operations, subprocess escape and checkout-file reads during exported collection. A second transport attempt after the synthetic permission denial is fatal. Success checks independent cash/vault/POL arithmetic, zero reconciliation delta, pinned/rechecked provenance, summary/full agreement, private checkpoint permissions and exit 0. Denial checks explicit uncollected/unconfirmed coverage, no fabricated block, zero response bytes/recovery, preserved checkpoint and exit 2. Installed verification after collection detects accidental runtime writes. There is no model grader, live network requirement or import/copy-only success assertion.

These checks establish synthetic consumer behavior and export integrity, not current financial state, actual host discovery or a successful live run. Run them only after integration alongside the existing offline suite; they do not authorize promotion, tagging or release.

## Controlled blind comparative dogfood

1. **Freeze the comparison before answers.** Record each reviewed immutable commit, manifest SHA-256, runtime digest and export receipt outside the skill. Preselect a small representative set from the map, including ordinary terse questions, partial evidence and denial. Fix prompts, provided evidence, task allowance and scoring criteria before viewing outputs; do not pick only cases that favor one candidate. A comparison with another package uses independently obtained authorized material, not copied runtime content.
2. **Control the host, not just the prompt.** Run both candidates on the same host/version, model/settings, normal permissions, tool catalog and resource budget. Use fresh sessions and one authoritative active copy per scope, verifying loaded path/revision after each switch. Keep other conversation history and the other candidate's answer out of context. Counterbalance A/B order across cases or repeats; retain the order and random label mapping privately. Test Hermes and OpenClaw separately rather than pooling different hosts as candidate effects. Do not change keys/providers/models to rescue one side.
3. **Separate passes.** Begin with package-only questions and explicitly supplied synthetic evidence, with no live-chain retrieval. Model-service access is not financial-source access. Later authorized live cases need fresh observations, selected scope and block/hash/time; never feed source financial snapshots into runtime files. Where both candidates cannot share the same authorized block/evidence basis, label timing/source differences as confounds instead of scoring numerical disagreement as a defect. A denied path ends that retrieval; no hidden restart, endpoint rotation or budget reset.
4. **Keep the first answer blind.** Give the natural question (and only the case's stipulated input), not the expected product route, answer, reference path or rubric. For example, ask “How much open interest is there for NetLong?” without coaching “cover both products”; do not add citation instructions when testing whether portable citations arise naturally. For `Use netstack`, expect the seven-topic menu without follow-up. Save the actual first answer and attempted tool actions before any repair prompt. Repeated runs use new sessions; retain all outcomes, not only the best.
5. **Blind the reviewers.** A coordinator labels packets A/B in a randomized, recorded order and withholds package identity and earlier critiques. Preserve substantive answer text, public citations, evidence dates/blocks and sanitized tool outcomes; remove identifying install paths/version labels only where they do not affect the claim under review. Reviewers score independently against the frozen case criteria before discussion or unblinding. If citations or wording reveal identity, record compromised blinding; do not call this a fully blind experiment.
6. **Score dimensions, not vibes.** Record each required/forbidden criterion with a supporting answer/trace excerpt. Separately assess accounting/units/beneficiaries, proof qualification/coverage, routing/discovery, concise useful answer, portable citations, refusal versus allowed research, terminal-stop behavior and delivery. Capture setup/loading, collection (including pacing/backoff), recovery as a subset, approval waits, post-collection delivery and end-to-end time only when measured. A collector timer is not an end-to-end promise; no client-visible answer is delivery failure even if server work finishes later.
7. **Unblind, triage, then decide.** Classify each case as pass, answer failure, host/access blocked or not exercised, and mark offline versus live. Useful graceful partial delivery is not complete accounting. Treat blocked/missing live cases as gaps, not wins or losses manufactured from imagined outputs. Resolve disagreements using the evidence and triage table above; record reviewer uncertainty. After any change, identify changed bytes and repeat affected cases on a newly bound candidate, retaining earlier failures. Candidate promotion needs the requested real-host/live evidence and independent review; unit-test counts, a synthetic green run, preference votes or one successful answer are insufficient.

Retain a compact private record per case: case/prompt, evidence mode, candidate binding, host/model/settings, loaded identity, order/label, permissions/capabilities, first answer, sanitized tool trace, checkpoints, timing, per-criterion verdict, reviewer disagreement, triage disposition and remaining gaps. Installation/scanner approval is separate from research acceptance. Do not infer safety enforcement from prompt compliance or a host that never offered the prohibited capability.

**Keep artifact handling coordinator-side.** Capture transcripts and checkpoints durably outside the runtime without adding private output directories or report-writing instructions to the answering agent's natural question. Those cues can contaminate consumer-facing citations and change the task being measured. Test an explicit user request for a saved report separately. Preserve any original failure; a new uncoached case after a harness change is a disclosed probe, not a repaired first answer, replacement pass or causal proof.

A local checkpoint is a diagnostic, not a public source. Its clearly labelled presence alongside appropriate public citations is not, by itself, a factual or security defect. Check whether it substitutes for evidence, misleadingly claims public accessibility, or exposes confidential material; keep portability and presentation findings separate from accounting correctness.

Award criterion credit for demonstrated reasoning, arithmetic, evidence or attempted-action behavior—not keyword overlap, confidence or repetition of the expected qualification.

Additional existing installation probes remain useful manual cases: Sleeve bond inventory is not minting, router returns are not new subscriber capital, and Sleeve receipts are not Treasury revenue; Credit `maxWithdraw=0` needs its VaultV2 sentinel semantics, separate liquidity/gates, Morpho offsets and fee-recipient-specific pending shares. Keep these as targeted accounting questions, not prerequisites to every research task. For an uncatalogued new NetLong market, require same-block discovery and applicable implementation evidence rather than address-pattern guessing or assumed zero exposure.

For live Book how-to replay, established Book context plus exactly one matching market permits an explicit assumption identifying that market and useful steps. Missing product context or multiple plausible matchups requires only the focused clarification needed to choose. Use `book_context_unique_match_missing_browser`, `book_context_multiple_giants_matches` and `giants_ambiguous_game` to distinguish these situations; absent rendered UI access qualifies exact controls/quotes rather than prohibiting explanation.
